# Handy — Mac 화면 공유 음성 입력

[English README](README.md) · [빌드 안내](BUILD.md) · [설치 안내](packaging/macos/INSTALL-KO.txt) · [원본 프로젝트](https://github.com/cjpais/Handy)

> [!IMPORTANT]
> **VNC 화면 공유에서 작동하게 하는 핵심은 `Use Shared Clipboard`를 OFF로 설정하는 것입니다.**
>
> **로컬 Mac의 ‘화면 공유’ 앱 → `Edit → Use Shared Clipboard`에서 체크를 해제하세요.** 한국어 메뉴에서는 **‘편집 → 공유 클립보드 사용’**입니다. 이어서 **`Edit → Send Clipboard`(클립보드 전송)가 활성화되어 있는지** 확인하세요.
>
> 이 설정을 켜 두면 새로 말한 내용 대신 **이전 문장이 반복해서 붙는 문제**가 생길 수 있습니다.

이 저장소는 [Handy](https://github.com/cjpais/Handy)의 비공식 수정본입니다. 로컬 음성 인식 기능에 **Mac 간 화면 공유의 클립보드 전송 처리**와 **macOS 입력·권한 처리 수정**을 더했습니다. 이 문서의 화면 공유 동작을 사용하려면 이 저장소의 소스로 만든 앱이 필요합니다.

## 어떤 방식으로 사용하는가

말하는 쪽인 **로컬 Mac에서 Handy를 실행**하고, macOS 기본 **‘화면 공유’ 앱으로 연결한 원격 Mac의 입력칸**에 전사 결과를 붙여넣습니다. 이 용도로 원격 Mac에 Handy를 설치할 필요는 없습니다.

| 위치                      | 준비할 항목                                                 |
| ------------------------- | ----------------------------------------------------------- |
| 로컬 Mac                  | 이 수정본의 Handy, 마이크, 다운로드한 음성 인식 모델        |
| 로컬 Mac의 권한           | Handy의 마이크 및 손쉬운 사용 권한                          |
| 로컬 Mac의 화면 공유 앱   | 원격 Mac에 **제어 모드(Control Mode)**로 연결               |
| 화면 공유의 클립보드 설정 | **Use Shared Clipboard = OFF**, **Send Clipboard = 활성화** |
| Handy의 붙여넣기 방식     | **Settings → Advanced → Paste Method → Clipboard (Cmd+V)**  |
| 원격 Mac                  | 일반적인 붙여넣기가 가능한 입력칸에 커서 배치               |

지원 대상은 **Apple의 화면 공유 앱으로 다른 Mac에 연결하는 경우**입니다. 다른 VNC 클라이언트나 Windows·Linux 원격 호스트에서의 동작은 이 연동의 검증 범위에 포함되지 않습니다.

## 설치와 최초 실행

1. 실행 중인 Handy가 있다면 메뉴 막대의 Handy 메뉴에서 완전히 종료합니다.
2. 이 저장소에서 빌드한 **DMG 설치 파일**을 열고 `Handy.app`을 `Applications` 폴더로 드래그합니다.
3. DMG를 추출하고 `/Applications/Handy.app`을 실행합니다.
4. Handy에 **마이크**와 **손쉬운 사용(Accessibility / Device Control and Data Access)** 권한을 허용합니다.
5. 사용할 언어를 지원하는 음성 인식 모델을 선택해 다운로드합니다. 한국어 입력에는 한국어를 지원하는 모델이 필요합니다.
6. 녹음 단축키와 사용할 마이크를 설정하고, 로컬 텍스트 편집기에서 먼저 음성 입력을 확인합니다.

앱 이름과 설정 저장 위치가 원본 Handy와 같으므로 기존 앱을 교체합니다. 기존 앱을 보관하려면 교체 전에 따로 옮겨 두세요. 설치 파일에는 배포자의 녹음·전사 기록·계정·API 키·개인 설정·다운로드한 인식 모델이 포함되지 않습니다.

배포 스크립트는 임시 **ad-hoc 서명**을 사용하며 **Apple Developer ID 서명·공증을 하지 않습니다**. 신뢰하는 출처의 앱을 macOS가 차단하면 한 번 실행을 시도한 뒤 **시스템 설정 → 개인정보 보호 및 보안 → 보안 → ‘확인 없이 열기’**에서 승인합니다. 자세한 절차는 [동봉 설치 안내](packaging/macos/INSTALL-KO.txt)와 [Apple 공식 안내](https://support.apple.com/ko-kr/102445)를 참고하세요.

## 화면 공유 설정: 이 순서대로 확인하세요

1. **원격 Mac**에서 화면 공유를 허용하고, **로컬 Mac**의 ‘화면 공유’ 앱으로 연결합니다. 연결과 제어 모드 설정은 [Apple 화면 공유 안내](https://support.apple.com/ko-kr/guide/mac-help/mh14066/mac)를 참고하세요.
2. 보기만 하는 모드가 아니라 **제어 모드(Control Mode)**인지 확인합니다.
3. Handy에서 **Settings → Advanced → Paste Method → Clipboard (Cmd+V)**를 선택합니다.
4. 로컬 Mac에서 **화면 공유 창을 맨 앞으로 가져옵니다**.
5. **화면 공유 앱의 메뉴 막대**에서 **Edit → Use Shared Clipboard**의 체크를 해제해 **OFF**로 만듭니다. Handy 설정이나 원격 앱의 메뉴에서 찾는 항목이 아닙니다.
6. 같은 메뉴의 **Edit → Send Clipboard**가 회색이 아닌 **활성 상태**인지 확인합니다. 전사할 때마다 Handy가 이 명령을 자동으로 실행합니다.
7. 원격 화면 안에서 글을 넣을 입력칸을 클릭합니다.
8. Handy 녹음 단축키로 녹음을 시작하고, 말한 뒤 녹음을 종료합니다.
9. 글이 입력될 때까지 **같은 화면 공유 창과 원격 입력칸의 포커스를 유지**합니다. 도중에 다른 창으로 이동하거나 클립보드에 다른 내용을 복사하지 마세요.

**연결을 다시 맺거나 다른 세션으로 바꾸면 `Use Shared Clipboard = OFF`와 `Send Clipboard` 활성 상태를 다시 확인하세요.** 이 OFF 설정은 이 수정본의 음성 입력을 위한 설정입니다.

## 왜 공유 클립보드를 꺼야 하나

이 수정본이 다루는 환경에서는 Handy가 로컬 클립보드에 새 전사 결과를 써도 원격 클립보드에 이전 내용이 남을 수 있습니다. 화면 공유 창에 계속 머문 채 여러 번 음성 입력하면 **첫 번째 문장은 들어가지만 두 번째부터 이전 문장이 반복되는 형태**로 드러납니다.

**Use Shared Clipboard를 끄면 Send Clipboard로 매번 새 내용을 명시적으로 전송할 수 있습니다.** Handy는 다음 순서로 처리합니다.

1. 로컬에서 음성을 인식하고 전사 결과를 클립보드에 기록합니다.
2. 화면 공유의 **Send Clipboard** 명령으로 원격 Mac에 전송을 요청합니다.
3. 전송 대기 후 같은 화면 공유 창에 `Cmd+V`를 보냅니다.
4. 붙여넣기 후 대기하고, 로컬 클립보드를 복원합니다. 대기 중 사용자가 새로 복사한 내용은 덮어쓰지 않습니다.

한글과 다른 유니코드 문자는 클립보드를 통해 전달합니다. **Send Clipboard를 사용할 수 없으면 붙여넣기를 실패로 처리**하며, 전사 결과는 Handy의 **History(기록)**에서 복구할 수 있습니다.

## 정상 작동 확인: 서로 다른 두 문장

설정 후에는 같은 원격 입력칸에서 다음을 확인하세요.

1. 원격 Mac의 TextEdit 같은 텍스트 편집기에서 빈 문서에 커서를 둡니다.
2. **“첫 번째 문장입니다.”**라고 말하고 입력될 때까지 기다립니다.
3. 화면 공유 창에서 벗어나지 않고 **“두 번째는 다른 내용입니다.”**라고 말합니다.
4. 두 번째 결과가 새 문장으로 들어가는지 확인합니다.

첫 문장이 반복되면 우선 **Use Shared Clipboard = OFF**와 **Send Clipboard 활성화**를 확인하세요. Handy의 History에는 두 번째 문장이 제대로 있는데 원격 화면만 첫 문장을 반복한다면, 음성 인식 결과와 클립보드 전달 결과가 다른 상황입니다.

## 문제 해결

| 증상                                                 | 확인할 내용                                                                                                   |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 이전 문장이나 복사했던 글이 반복됨                   | 로컬 화면 공유의 **Use Shared Clipboard를 OFF**로 바꾸고 **Send Clipboard** 활성 상태 확인                    |
| Send Clipboard가 회색이거나 보이지 않음              | 공유 클립보드 OFF, 연결 유지, Mac 간 연결, **제어 모드**, Apple 기본 화면 공유 앱 사용 여부 확인              |
| History에는 새 문장이 있지만 원격 입력칸은 비어 있음 | Handy의 **Clipboard (Cmd+V)** 설정·손쉬운 사용 권한 확인, 원격 입력칸을 클릭한 뒤 일반 붙여넣기가 되는지 확인 |
| 녹음이 시작되지 않음                                 | 마이크 권한·선택한 마이크·모델·녹음 단축키 확인, 로컬 편집기에서 먼저 테스트                                  |
| Handy 항목이 이미 있는데 권한 화면이 Waiting에 머묾  | 아래의 기존 권한 항목 복구 절차 진행                                                                          |
| 연결이 느릴 때 붙여넣기가 누락됨                     | **Paste Delay (Before/After)**를 늘리고 전사가 끝날 때까지 같은 창과 입력칸 유지                              |
| 창을 바꾼 뒤 붙여넣기 실패                           | 원래 원격 창과 입력칸을 다시 선택하고 History에서 전사 결과를 확인한 뒤 재시도                                |

### 붙여넣기 지연 조정

Handy 설정 창에서 **`Cmd+Shift+D`**를 눌러 Debug를 표시하면 다음 값을 조정할 수 있습니다.

| 설정                 | 의미                                               | 화면 공유 최소 대기 |
| -------------------- | -------------------------------------------------- | ------------------- |
| Paste Delay (Before) | 클립보드 전송 요청 후 붙여넣기 키를 보내기 전 대기 | **500 ms**          |
| Paste Delay (After)  | 붙여넣기 후 로컬 클립보드를 복원하기 전 대기       | **1,500 ms**        |

사용자가 더 큰 값을 설정하면 그 값을 유지합니다. 네트워크가 느리면 먼저 필수 클립보드 설정을 확인한 다음 지연을 늘려 보세요. 이 시간은 전송 여유를 주기 위한 값이며, 원격 앱의 수신 완료를 확인하는 장치는 아닙니다.

화면 공유에서는 실험적 **Reliable Paste** 설정이 켜져 있어도 일반 클립보드 경로를 사용합니다. 로컬에서 클립보드를 읽었다는 사실만으로 원격 앱의 붙여넣기 완료를 알 수 없기 때문입니다.

### 기존 Handy 권한 항목이 인식되지 않을 때

앱을 교체한 뒤 macOS 권한 목록에 이전 실행 파일의 정보가 남을 수 있습니다. **목록에 Handy가 있다는 사실만으로 현재 앱에 권한이 부여된 것은 아닙니다.**

1. Handy를 완전히 종료합니다.
2. 시스템 설정의 **개인정보 보호 및 보안 → 손쉬운 사용**에서 기존 Handy 항목을 제거합니다.
3. 설치한 **`/Applications/Handy.app`**을 다시 추가하고 권한을 켭니다.
4. Handy를 다시 실행하고 권한 상태를 확인합니다.

권한·입력 처리 수정과 실제 환경에서 추가 확인이 필요한 항목은 [macOS 입력·권한 수정 기록](docs/macos-input-safety.md)에 정리되어 있습니다.

## 소스에서 빌드하기

플랫폼별 의존성과 모델 준비는 [BUILD.md](BUILD.md)를 따르세요. 이 수정본을 가져오는 명령은 다음과 같습니다.

```bash
git clone https://github.com/seionwon/Handy.git
cd Handy
bun install
```

macOS에서 빌드 의존성을 준비한 뒤 Apple Silicon과 Intel용 **Universal DMG**를 만들려면 다음을 실행합니다.

```bash
rustup target add aarch64-apple-darwin x86_64-apple-darwin
bun scripts/build-macos-share.ts
```

전체 Xcode를 사용하는 경우의 환경 설정 등은 [Universal 배포 빌드 안내](BUILD.md#macos-screen-sharing-distribution-universal)를 참고하세요. 이 빌드는 macOS 11.0 이상을 대상으로 하지만, 모든 macOS 버전과 Intel 실기기에서 검증되었다는 뜻은 아닙니다. 별도로 받은 설치 파일이 arm64 전용이면 Apple Silicon Mac용입니다.

결과물은 `src-tauri/target/share/`에 생성됩니다.

- `Handy-ScreenSharing-<버전>-universal.dmg`: 앱·설치 안내·라이선스가 들어 있는 설치 파일
- 같은 이름의 `.dmg.sha256`: SHA-256 체크섬
- `INSTALL-KO.txt`: 한국어 설치 안내

배포할 때는 **DMG 파일을 그대로 전달**하면 됩니다. 파일 첨부가 어려우면 DMG 다운로드 링크를 공유하세요. 이 배포본은 원본 앱의 자동 업데이트로 수정 사항이 사라지는 일을 막기 위해 앱 내 업데이트를 비활성화합니다. 새 수정본은 DMG로 직접 교체합니다.

## 개인정보와 저장 데이터

- **음성 인식은 로컬에서 실행**합니다. 모델을 처음 다운로드할 때는 인터넷 연결이 필요합니다.
- 선택적 후처리 기능에 외부 API를 설정하면 전사 텍스트가 해당 제공자로 전송될 수 있습니다.
- 화면 공유 음성 입력은 전사 결과를 **원격 Mac의 클립보드로 전송**합니다.
- 녹음과 전사 기록의 보관 설정은 Handy에서 확인할 수 있습니다. 로그나 문제 보고를 공유할 때는 개인적인 전사 내용과 인증 정보를 제거하세요.
- 보안 수정 내역과 남은 검증 범위는 [보안 점검 기록](docs/macos-input-safety.md#보안-점검)을 참고하세요.
